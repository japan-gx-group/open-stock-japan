# セットアップガイド

OpenStock Japan を自社で動かすための手順です。ローカルで試すだけなら [README](../README.md) の「はじめかた」で足ります。

## 1. 必要なもの

- Node.js 24 以上
- Supabase のプロジェクト（[Supabase Cloud](https://supabase.com/) または自前のホスト）。ローカルで試す場合は Docker
- アプリを動かす場所（Vercel、AWS Amplify、自前のサーバなど、Next.js が動く環境）

1 つのデプロイで 1 社を管理する前提です。複数の会社を管理する場合は、会社ごとにデプロイと Supabase プロジェクトを分けてください。

## 2. 設定

### 2-A. データベース

```bash
npx supabase link --project-ref <プロジェクトの ref>
npx supabase db push
```

マイグレーション（`supabase/migrations/`）がテーブル・権限・Storage のバケットを作ります。
本番にはデモデータ（`supabase/seeds/demo/`）を入れないでください。

Supabase の Auth 設定では、**メールでの新規登録（サインアップ）を無効**にします。ユーザーは、初回セットアップと招待の受諾でだけ作られます。

あわせて、パスワードの決まり（12 文字以上・英字と数字）、二要素認証（TOTP）の有効化、セッションの期限を、ローカルの `supabase/config.toml` と同じ値に設定します。設定する項目と、本番に入れたあとに確かめること（ログインが監査ログに残るか、など）は [system-audit.md](system-audit.md) の「5.1 Supabase の設定」「6. 導入したときの確認」にあります。

### 2-B. 環境変数

`.env.example` をコピーして値を設定します。

| 変数 | 必須 | 内容 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ○ | Supabase の API URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ○ | anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | ○ | service_role key。**サーバだけに置く**（ブラウザに出さない・コミットしない） |
| `APP_URL` | 推奨 | アプリの公開 URL（招待メール・共有リンクの URL と、別のサイトからの操作を弾く確認に使う） |
| `SETUP_TOKEN` | 本番の初回の登録に必須 | 初回の登録（`/signup`）で入力する合言葉。16 文字以上の乱数。この値を入力した人だけが最初の管理者を登録できる（3. 初回セットアップ） |
| `TRUSTED_PROXY_HOPS` | 任意 | アプリの前にあるプロキシの段数（既定は 1）。監査ログの接続元の決め方に使う |
| `RESEND_API_KEY` / `INVITE_EMAIL_FROM` | 任意 | 招待メールの送信（2-C） |
| `AI_PROVIDER` / `AI_API_KEY` | 任意 | AI の設定（2-I） |

`SUPABASE_SERVICE_ROLE_KEY` は、株主名簿を含むすべてのデータを読み書きできる鍵です。漏れた場合はすぐに Supabase 側で再発行してください。

### 2-C. 招待メールの設定（任意）

メンバーや株主を招待するときにメールを送るには、[Resend](https://resend.com/) の API キーと送信元アドレスを設定します。

```
RESEND_API_KEY=...
INVITE_EMAIL_FROM="OpenStock Japan <noreply@your-domain.example>"
```

未設定でも招待は使えます。その場合は、招待の画面に表示されるリンクをコピーして、自分で相手に送ってください。招待リンクの有効期間は 7 日です。

### 2-D. 本番運用時のセキュリティヘッダ

- HTTPS で公開してください。HSTS は本番ビルドでだけ返します（`HSTS_MAX_AGE`、`HSTS_INCLUDE_SUBDOMAINS` で調整）。
- リバースプロキシの下で動かす場合は `APP_URL` を必ず設定してください（Host ヘッダから URL を作らないため）。

### 2-I. AI の設定（任意）

AI は、文書からの取り込み・フォームの入力補助・文章の下書き・文書テンプレートの作成に使います。設定しなくても、AI 以外の機能はすべて使えます（文書テンプレートも、手で書いたひな形から文書を作れます）。

提供元は **Anthropic（Claude）・Google（Gemini）・OpenAI** から選べます。設定の方法は 2 つあります。

**方式 A（既定）: 環境変数に API キーを置く**

```
AI_PROVIDER=google        # anthropic / google / openai
AI_API_KEY=...
```

**方式 B: 管理者が画面から API キーを登録する**

```
AI_ALLOW_KEY_REGISTRATION=true
AI_ENCRYPTION_KEY=...      # openssl rand -base64 32 で作る。SUPABASE_SERVICE_ROLE_KEY とは別の値にする
# AI_ALLOWED_PROVIDERS=anthropic,google   # 登録を認める提供元（省略時は 3 社すべて）
```

登録したキーは AES-256-GCM で暗号化して保存します。`AI_ENCRYPTION_KEY` を変えると、登録済みのキーは読めなくなります（登録し直し）。

どちらの方式でも、**モデルは管理者が「組織・メンバー設定 > AI の設定」で選びます**（選ぶまで AI の機能は使えません）。

**送る内容と鍵の条件**

- AI には、利用者が貼り付けた文章、添付した PDF・画像、下書きの材料（会議の内容・議案・決算の数字など）を送ります。契約書や株主名簿には個人情報と機密情報が含まれます。
- 文書テンプレートの作成では、会社の機関設計（取締役会・監査役の有無など）と、利用者が入力した要望・参考の文面、または貼り付けたひな形の文面を送ります。会社名・株主・金額などの台帳の値は送りません（ひな形には差し込み項目として書かれ、文書を作るときに、AI を使わずに置き換えます）。
- 使う API キーは、**法人契約で、送った内容をモデルの学習に使わない条件のもの**に限ってください。Gemini は有料枠のキーを使ってください（無料枠は入力が製品の改善に使われることがあります）。各社の最新の利用規約・データの取扱いを確認し、社内の情報管理の担当と、必要なら投資契約上の守秘義務も確認してください。
- 送信の前に、送り先（提供元とモデル）を画面に表示します。AI を呼んだ記録（誰が・いつ・どの用途で・どのモデルに）は監査ログに残ります。送った内容と AI の出力は監査ログに残しません。
- AI の出力は候補として表示するだけで、台帳に書き込むのは人が確かめて保存したときだけです。

## 3. 初回セットアップ

デプロイ後、`/signup` を開いて最初の管理者アカウントと会社を登録します。この画面は、組織がまだ 1 つも無いときだけ開けます。

本番（`NODE_ENV=production`）では、この登録に**セットアップ用の合言葉**が要ります。デプロイの前に、環境変数 `SETUP_TOKEN` に 16 文字以上の乱数（`openssl rand -base64 24` など）を設定し、登録の画面でその値を入力してください。設定していないと、登録の画面は開けません。公開してから最初の登録までのあいだに、別の人が先に登録して管理者になるのを防ぐためです。最初の登録が済んだら、`SETUP_TOKEN` は消して構いません。

続けて、次の順に登録すると各画面の計算が揃います。

1. **会社情報・役員**: 登記事項証明書と定款のとおりに、資本金・発行可能株式総数・機関設計・定款の定め・事業年度・役員を登録します（AI 取り込みで登記事項証明書の PDF から読み取ることもできます）。
2. **株主・権利者**と**株式の異動**: 設立時の発行から順に登録します。既存の株主名簿から始める場合は、ある日付時点の持株をまとめて登録できます。
3. **種類株式・ラウンド・新株予約権・J-KISS**: 該当するものを登録します。
4. **メンバーの招待**: 管理部の担当者を「メンバー」、閲覧だけの人を「閲覧のみ」で招待します。
5. **株主の招待**: 株主名簿の「権利者」タブから、株主を株主ポータル（`/external-portal`。社外の株主がログインして見る画面）に招待します。社内の人は、サイドバーの「株主ポータルを見る」から公開中の内容を確認できます。

## 4. ロール

| ロール | できること |
|---|---|
| 管理者 | すべて。組織の設定、メンバーと株主の招待、AI の設定、会社情報の変更 |
| メンバー | 業務データ（株主・株式・会議・決算・文書）の閲覧と編集 |
| 閲覧のみ | 業務データの閲覧 |
| 監査人 | 業務データと監査ログ・アカウントの棚卸しの閲覧（何も変えられない） |
| 株主 | 株主ポータルだけ。自分の保有状況と、公開されたお知らせ・決算・文書 |

株主名簿には個人情報が含まれます。社内のロールは、業務で必要な人だけに付与してください。

操作はすべて監査ログに残ります（だれが・いつ・どこから・何を・どう変えたか）。監査ログの見方、二要素認証、
本番の Supabase に合わせる認証の設定、バックアップ、定期的に行うことは [system-audit.md](system-audit.md) にまとめています。
本番に入れたら、同じ文書の「導入したときの確認」を一通り行ってください。

## 5. バックアップと保存期間

- データベースと Storage（`documents` バケット）の両方をバックアップしてください。Supabase Cloud の自動バックアップに加えて、定期的なエクスポートを勧めます。
- 会社法が求める保存・備置きの期間（株主総会・取締役会の議事録は 10 年、計算書類は備置き 5 年・保存 10 年など）は [docs/legal/](legal/) を参照してください。このアプリに保管するだけで法令上の備置き義務を満たすかどうかは、備置きの方法（本店での閲覧に応じられるか）によります。

## H. 困ったとき

### H-1. ログインできない・画面が真っ白

- `.env.local` の Supabase の URL とキーが正しいか、Supabase が起動しているかを確認します。
- サーバのログ（`LOG_LEVEL=debug` で詳しく出ます）を確認します。

### H-2. 管理者がいなくなったときの復旧

管理者が 1 人もログインできなくなった場合は、Supabase の SQL Editor（または service_role で接続した psql）で、社内のメンバー 1 人を管理者に変更します。

```sql
update profiles set role = 'admin' where email = '<メンバーのメールアドレス>';
```

通常の操作では、組織の管理者が 0 人になる変更はデータベースが拒否します。

### H-3. AI が使えない

- 「組織・メンバー設定 > AI の設定」で、状態（鍵が設定されているか・モデルが選ばれているか）を確認します。
- 回数の上限（用途ごとに 1 分・1 日あたり、組織全体で 1 日 500 回）に達すると、しばらく使えません。
- 4MB を超えるファイルは AI に送れません（文書の保管はできます）。
